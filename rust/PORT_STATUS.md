# Rust port — status

Side-by-side port of the Python app (branch `ui`) under `rust/`, following
`rust_port_plan.md`. Nothing in the Python tree is modified by the port; the
Python app remains the reference implementation and the golden generator.
Nothing has been committed.

Build: `cd rust && cargo build --release -p xpr-app` (toolchain 1.98, msvc);
the resulting exe is self-contained (data and images embedded at build time,
MSVC CRT linked statically via `rust/.cargo/config.toml`; see `TESTING.md`
§ 0).
Standalone program / release zip: `py -3.14 rust/windows_build.py --smoke`
→ `dist/rust/pkmn_xp_router.exe` and
`dist/rust/windows_pkmn_xp_router_<version>.zip` (one top-level exe, the
layout both updaters expect), verified by running the packaged exe from an
empty directory.
Run: `cd rust && cargo run --release -p xpr-app [-- --debug]` (uses the same
config / data directories as the Python app; see `TESTING.md` § 0 for an
isolated run and the test-hook environment variables).
Tests: `cd rust && cargo test --workspace`.
Golden verification: `cargo run --release -p xpr-golden -- verify <golden_dir>` (usage in `crates/xpr-golden/src/main.rs`; the Python corpus generator was removed with the Python app). To check a change against the previous build without a corpus, run `xpr-golden dump <dir> --battles <route.json>...` with both builds and diff the two directories. The PP tracking change was checked this way: 67 routes and 8,428 battle summaries identical, apart from the intended PP-item warnings.
PP tracking: `docs/rust_port/design/pp_tracking/PLAN.md`; `cargo run --release -p xpr-app --bin pp_bench -- <route.json>...` times the PP ledger.
Test plan: `TESTING.md`. Divergences: `docs/rust_port/KNOWN_ISSUES.md`.

## Dex page (2026-10-03)

Solodex (`A:\Dropbox\stp-projects\programs\solodex`, the Electron
Pokémon reference app) is folded into the router as the **Dex** page, so a
route can be planned, recorded and refined in one program. Open it from the
landing page ("Pokédex"), the **Dex** menu, or Ctrl+K (`toggle_dex`); Back /
Ctrl+K return to the page it was opened from. The Dex menu can move it into
a window of its own (beside the editor on a second monitor) and holds
Solodex's View-menu toggles (cross out banned / postgame / conditional
moves, the banned-moves editor, movepool differences, Bulk / WBST / UBST)
and the Dex's key list. Settings persist in the config's `dex_settings`.

Tabs (Solodex's, F1-F9 as there): Pokédex (filterable species list, detail
with stats / rankings / matchups / evolutions, movepool with TM / tutor
popovers, test-set coverage, two- and three-species and cross-game
comparisons), EVs, Trainers (list, party cards, speed rankings, team-order
calculator, "Add to Route", "Calc Damage"), Stats (outspeed scouting),
Damage, Movedex, Natures, Misc (hit probability, effective accuracy,
multi-hit). Space / Shift+Space / Ctrl+Shift+Space open the Pokémon, trainer
and move searches. Solodex's Route tab and map are not ported (the router
has its own); neither are its graphic exports, Bulbapedia article popovers
(replaced by links that open the browser) or issue reporter.

Data: the Pokédex-side tabs use Solodex's data (`dex_data/`, 21 games, gens
1-9; `node tools/dex_data/sync.mjs [<solodex>]` regenerates it; ~7.7 MB in
the binary). Trainers, Stats' major battles and Damage use the router's own
trainer tables and engine, so names and numbers match the route editor and
custom gens work. The Damage tab is the editor's battle summary
(`BattleSummaryUi` in a free-form mode) for a player built in its side panel
or copied from the open route (the state entering the selected event); it
starts on the route's Pokémon, or on the Pokédex's selection and right-clicked
test set.

Code: `xpr-dex` (data), `xpr-dex-ui` (the page; one cargo feature per tab),
`xpr-app/src/dex_damage.rs` (Damage tab), `Page::Dex` / the Dex menu in
`app.rs`. Porting notes: `docs/rust_port/design/dex/PORTING.md`. Headless
pictures: `cargo run -p xpr-dex-ui --example dex_png -- --tab trainers --version Crystal --trainer "Leader Falkner" --out x.png`
and `cargo run -p xpr-app --example dex_damage_png -- out.png Emerald Mudkip "Leader Roxanne"`;
smoke: `XPR_SMOKE_ACTION=dex XPR_SMOKE_DEX_TAB=<tab>`. Tests:
`xpr-dex/tests/data.rs`, `xpr-dex-ui/tests/*.rs` (a file per tab),
`xpr-app/tests/dex_page.rs`, and the Dex cases in `modal_input.rs`.

## World map (2026-09-24)

pokemap (`~/Documents/pokemap`) is integrated per
`docs/rust_port/design/world_map/SPEC.md`, phases 0–4 (the MVP): the map
pack for the seven gen 1–3 games is committed under `map_data/` (2.8 MB
deflated in the binary), `xpr-map` composites the maps at runtime (Yellow's
world in 18 ms, Emerald's 137 Mpx world in 79 ms, release), and the Map tab
of the right pane / a separate window shows it beside the route list with
"add to route" (trainers, items, wild encounters, whole maps) and "show on
map" (Map menu, Ctrl+Shift+M, the editor's Map button). Trainer link
coverage from the pipeline: Yellow 100 %, Red/Blue 98 %, Gold/Silver and
Crystal 95 % (the S.S. Aqua cabins are missing from pokemap's data),
Emerald 97 %, FireRed/LeafGreen 96 %, Ruby/Sapphire 90 % (the rest are
unplaced beta trainers). Overworld sprites (gen 1 town palettes, gen 2 NPC
palettes incl. night, gen 3 keyed frames) followed the same day, drawn from a
texture atlas. The encounter cards (2026-09-25) are a Pokémon / Level /
Rate / EV yield table — the EV column for gens 3+ from the router's own
species data — wider than the object cards and scrolling past 60 % of the
viewport; `examples/map_card_png.rs` renders any card to a PNG headless.
Map display names (`maps.json` `display`, 2026-09-25) follow the router's
location style — "Route 1", "Mt. Moon B1F", "SS Anne", "Silph Co.",
"Hall of Fame" — via `displayName` in pokemap's `pipeline/export-router.js`
(1,041 of 2,546 names changed when the pack was regenerated).
Graphics tools (2026-09-25, `docs/rust_port/design/world_map/
GRAPHICS_TOOLS_PLAN.md`): PNG export of the view / a marquee selection / one
map / the whole world at 1–8× with the toggled layers (`xpr-map::export`
renders in bands with progress and cancel; the app draws markers, grid,
labels and the trip path over it through the software rasteriser; Map menu
"Export Map Image…" Ctrl+Shift+P, "Copy Map View", `XPR_SMOKE_EXPORT=map`),
copy to the clipboard, marquee (M / Shift+drag) and ruler (R) tools with a
floating Zoom / Export / Copy / Add-trainers bar, a grid and map-name
overlay, a "Layers ▾" popup replacing the toolbar chips, a navigator
minimap with a zoom-presets menu on the readout, trainer / item search in
the map search box, Tab / Shift+Tab marker navigation, follow-selection,
and the trip path overlay (one folder at a time, SPEC D15 / §13, phase 1:
straight segments, no warp projection). Left for later: warp projection and
least-steps paths (SPEC §13.2–13.3), per-event pinned anchors, gen 4/5.

## Performance pass (2026-09-11): pre-fight candies

Target: the time from a "+" candy click to the redrawn damage ranges. Before,
a click waited for a 250 ms debounce and then paid for two undo snapshots
(full JSON serialisation of the route), a full-route recalculation, and two
battle-summary refreshes (the operation's own and the frame's
`route_changed` cascade, which also discarded unsaved selections -- review
finding 11), while every frame recomputed the route list's column values.

What changed (results bit-identical: `xpr-golden verify` over a fresh
Python corpus of the 4 test routes plus the 60 largest saved routes with
every fight's battle summary matched on everything Python computed -- the
only diffs are the 16 fights where Python itself crashes, see
`docs/rust_port/REVIEW.md` "Golden results" 1 -- and the 437 recorded damage
cases and the route regression tests are unchanged; new tests cover the new
code paths):

| Change | Where | Test |
|---|---|---|
| Incremental recalculation: an insert / replace / single removal recomputes from the changed position to the end of the route and stops early when a folder's leaving state is unchanged (`Router::recalc_from`); moves, transfers, batch removals, DV / level-up changes still do a full pass | `xpr-engine/src/recalc.rs`, `router.rs` | `xpr-engine/tests/incremental_recalc.rs` (also run over 8 big real routes of gens 1-4 incl. custom gens via `XPR_ROUTE_FILES`) |
| Undo snapshots are structural copies of the tree serialised only when restored, and the redundant pre-operation snapshot (Python overwrites it before use) is skipped | `xpr-engine/src/undo.rs` | `xpr-engine/tests/undo_snapshot.rs` |
| `apply_item` computes labels once and shares the state `Arc` for pass-through events (notes / save / heal) | `xpr-engine/src/recalc.rs` | golden verify |
| Kill-percentage search: memo keyed without the redundant roll multiplier, multiplicative hashing, power table; same float operations in the same order | `xpr-calc/src/damage.rs` | `xpr-calc/tests/kill_search_equivalence.rs` (6,000 random cases bit-identical to the straight port) |
| One battle reload per operation (`take_handled_route_change`), candy clicks applied immediately with undo coalescing of bursts | `xpr-app/src/battle.rs`, `battle_ui.rs`, `event_details.rs`, `controller.rs` | `xpr-app/tests/prefight_candies.rs` |
| Route list caches column values / fit widths per rebuild instead of per frame (review finding 23) | `xpr-app/src/route_list.rs` | frame log |

Measured with `candy_bench` (release, this machine; compute only, no drawing):

In the app (`XPR_FRAME_LOG=1 XPR_SMOKE_ACTION=candy` on the crystal route):
a click now costs one ~5 ms frame (mutation + summary + draw) followed by
one ~6 ms frame for the route-list rebuild, instead of 250 ms + a 31 ms
frame; idle frames on that route went from ~4 ms to ~2.5 ms.

Left on the table: the suffix recalculation is ~3 µs per event
(inventory / state clones, labels, per-item definition copies), so an
early-route candy on a 2,800-event route still spends ~8 ms there; the
vitamin steppers keep their debounce and multi-mutation path.

## Divergences from Python (intentional, documented in docs/rust_port/KNOWN_ISSUES.md)

See that file; the short list: crashes become error results, gen 3/5 battle-stat mutation (Appendix B 14) is not reproduced, null `base_xp` in a custom gen loads as 0 and only errors when the mon is fought, Appendix B "Python-first" fixes (3, 4) were ported as-is because the Python code was not to be changed, the Qt transfer/new-folder dialogs (which call missing `Router` methods) use the tkinter logic, screenshots are opaque, and dialogs/popovers are in-window overlays.
