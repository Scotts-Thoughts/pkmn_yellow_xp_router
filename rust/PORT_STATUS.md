# Rust port — status

Side-by-side port of the Python app (branch `ui`) under `rust/`, following
`rust_port_plan.md`. Nothing in the Python tree is modified by the port; the
Python app remains the reference implementation and the golden generator.
Nothing has been committed.

Build: `cd rust && cargo build --release -p xpr-app` (toolchain 1.98, msvc);
the resulting exe is self-contained (data and images embedded at build time,
MSVC CRT linked statically via `rust/.cargo/config.toml`; see `TESTING.md`
§ 0).
Standalone program / release zip: `py -3.14 rust/windows_build.py --smoke`
→ `dist/rust/pkmn_xp_router.exe` and
`dist/rust/windows_pkmn_xp_router_<version>.zip` (one top-level exe, the
layout both updaters expect), verified by running the packaged exe from an
empty directory.
Run: `cd rust && cargo run --release -p xpr-app [-- --debug]` (uses the same
config / data directories as the Python app; see `TESTING.md` § 0 for an
isolated run and the test-hook environment variables).
Tests: `cd rust && cargo test --workspace`.
Golden verification: `cargo run --release -p xpr-golden -- verify <golden_dir>` (usage in `crates/xpr-golden/src/main.rs`; the Python corpus generator was removed with the Python app).
Test plan: `TESTING.md`. Divergences: `docs/rust_port/KNOWN_ISSUES.md`.

## Performance pass (2026-09-11): pre-fight candies

Target: the time from a "+" candy click to the redrawn damage ranges. Before,
a click waited for a 250 ms debounce and then paid for two undo snapshots
(full JSON serialisation of the route), a full-route recalculation, and two
battle-summary refreshes (the operation's own and the frame's
`route_changed` cascade, which also discarded unsaved selections -- review
finding 11), while every frame recomputed the route list's column values.

What changed (results bit-identical: `xpr-golden verify` over a fresh
Python corpus of the 4 test routes plus the 60 largest saved routes with
every fight's battle summary matched on everything Python computed -- the
only diffs are the 16 fights where Python itself crashes, see
`docs/rust_port/REVIEW.md` "Golden results" 1 -- and the 437 recorded damage
cases and the route regression tests are unchanged; new tests cover the new
code paths):

| Change | Where | Test |
|---|---|---|
| Incremental recalculation: an insert / replace / single removal recomputes from the changed position to the end of the route and stops early when a folder's leaving state is unchanged (`Router::recalc_from`); moves, transfers, batch removals, DV / level-up changes still do a full pass | `xpr-engine/src/recalc.rs`, `router.rs` | `xpr-engine/tests/incremental_recalc.rs` (also run over 8 big real routes of gens 1-4 incl. custom gens via `XPR_ROUTE_FILES`) |
| Undo snapshots are structural copies of the tree serialised only when restored, and the redundant pre-operation snapshot (Python overwrites it before use) is skipped | `xpr-engine/src/undo.rs` | `xpr-engine/tests/undo_snapshot.rs` |
| `apply_item` computes labels once and shares the state `Arc` for pass-through events (notes / save / heal) | `xpr-engine/src/recalc.rs` | golden verify |
| Kill-percentage search: memo keyed without the redundant roll multiplier, multiplicative hashing, power table; same float operations in the same order | `xpr-calc/src/damage.rs` | `xpr-calc/tests/kill_search_equivalence.rs` (6,000 random cases bit-identical to the straight port) |
| One battle reload per operation (`take_handled_route_change`), candy clicks applied immediately with undo coalescing of bursts | `xpr-app/src/battle.rs`, `battle_ui.rs`, `event_details.rs`, `controller.rs` | `xpr-app/tests/prefight_candies.rs` |
| Route list caches column values / fit widths per rebuild instead of per frame (review finding 23) | `xpr-app/src/route_list.rs` | frame log |

Measured with `candy_bench` (release, this machine; compute only, no drawing):

| Route | Fight | Before | After |
|---|---|---|---|
| e-geodude-1-20359r (634 groups, Emerald) | Rival Steven, 6 mons (last third) | 9.6 ms | 0.9 ms |
| e-geodude-1-20359r | Roxanne (early) | ~9.6 ms | 3.7 ms |
| y-weedle-1-failed (2,523 groups, custom Yellow) | Rival3 (end) | 25.2 ms | 1.9 ms |
| y-weedle-1-failed | Brock (start) | ~25 ms | 8.1 ms |
| crystal-sunflora-1-refined (2,834 groups) | Red (end) | 29.2 ms | 2.8 ms |
| crystal-sunflora-1-refined | Falkner (start) | ~29 ms | 11.1 ms |
| battle summary refresh, 6-mon gen 2 fight | | 3.8 ms | 0.8 ms |
| full recalc, crystal route | | 12.7 ms | 8.5 ms |

In the app (`XPR_FRAME_LOG=1 XPR_SMOKE_ACTION=candy` on the crystal route):
a click now costs one ~5 ms frame (mutation + summary + draw) followed by
one ~6 ms frame for the route-list rebuild, instead of 250 ms + a 31 ms
frame; idle frames on that route went from ~4 ms to ~2.5 ms.

Left on the table: the suffix recalculation is ~3 µs per event
(inventory / state clones, labels, per-item definition copies), so an
early-route candy on a 2,800-event route still spends ~8 ms there; the
vitamin steppers keep their debounce and multi-mutation path.

## Divergences from Python (intentional, documented in docs/rust_port/KNOWN_ISSUES.md)

See that file; the short list: crashes become error results, gen 3/5 battle-stat mutation (Appendix B 14) is not reproduced, null `base_xp` in a custom gen loads as 0 and only errors when the mon is fought, Appendix B "Python-first" fixes (3, 4) were ported as-is because the Python code was not to be changed, the Qt transfer/new-folder dialogs (which call missing `Router` methods) use the tkinter logic, screenshots are opaque, and dialogs/popovers are in-window overlays.
