# The Dex page: porting Solodex into the router

The router hosts Solodex's reference views (Pokédex with movesets and
comparisons, EV tables, trainers, stats, damage, movedex, natures, misc
calculators) on a **Dex page**, so a route can be planned, recorded and refined
in one program. Solodex's Route tab and its map are not ported: the router
has its own route editor and world map.

Solodex source (read-only reference): `A:\Dropbox\stp-projects\programs\solodex`
(`src/renderer/src/`, React + TypeScript). Port behaviour faithfully: the same
columns, sort orders, filters, labels, colours, tooltips and edge cases. The
look is Solodex's (layout, colours, its navy grays) in the router's fonts.

## Layout

| Crate / path | What |
|---|---|
| `dex_data/` (repo root) | Solodex's data as JSON + the HOME sprites. Generated by `node tools/dex_data/sync.mjs` from Solodex's `data_objects-main/`; never edit by hand. |
| `rust/crates/xpr-dex` | The data layer (Solodex `data/index.ts`, `forms.ts`, `speciesIndex.ts`, `games.ts`, `formSprites.ts`, `utils/damage/stats.ts`, `moveNameCanonical.ts`, `tmhmSort.ts`). No egui. |
| `rust/crates/xpr-dex-ui` | The page: `shell.rs` (tab bar, game toggle, Pokédex list/detail split, keys, search overlays), `state.rs` (shared state + persisted settings), `widgets.rs`, `palette.rs`, `images.rs`, `testkit.rs`, and one module per tab under `src/views/`. |
| `rust/crates/xpr-app` | Hosts the page (`Page::Dex`, the Dex menu, the Damage tab which reuses the router's battle summary). |

Each tab is a cargo feature of `xpr-dex-ui` (`pokedex`, `movepool`, `compare`,
`trainers`, `evs`, `movedex`, `stats`, `misc`) so it builds and tests alone.

## Data

Dex tabs (Pokédex, Movedex, EVs, Stats, Natures) use **`xpr-dex`**: 21 games
(gens 1-9) by Solodex's names (`"Red and Blue"`, `"Black 2 and White 2"`).
Functions mirror Solodex's in snake_case: `get_pokemon_data(name, game)`,
`get_all_pokemon_for_game`, `get_all_pokemon` (species index), `get_games_for_pokemon`,
`get_move_data(name, game)` (alias-aware: Faint Attack / Feint Attack),
`get_moves_for_gen`, `move_across_gens`, `move_introduction_gen`, `tmhm_code`,
`compare_tmhm`, `type_matchups`, `defense_matchups`, `offensive_multiplier`,
`types_for_game`, `types::ability_immunity_type`, `get_ranking(RankKind, game, filter)`
(stat / bulk / BST / WBST / UBST rankings), `get_encounters_for_pokemon`,
`natures::natures()`, `unobtainable_move_sets(game, &user_bans)`,
`stats::{calc_gen12_stats, calc_gen3_stats, nature_mods}`,
`forms::classify_form`, `species::display_name` (`Nidoran_F` -> `Nidoran♀`),
`resolve_species(any name)` (router / typed names -> Dex key),
`text::locale_cmp` (JS `localeCompare`), `games::*` (gen groups, colours,
abbreviations, router-version mapping). Learnsets are already respelled for
each game. Move data exists for gens 1-9.

Trainers and Damage use **the router's own data** (`xpr-data`), so trainer
names and numbers match the route editor, and custom gens work:
`cx.registry.get_version(version) -> Result<Arc<GenData>>`, then
`gen.trainer_db()` (`iter()`, `get_trainer(name)`; `Trainer { name,
trainer_class, location, money, pkmn: Vec<EnemyPkmn>, rematch, trainer_id,
double_battle, .. }`; `EnemyPkmn { name, level, cur_stats: StatBlock, move_list,
held_item, ability, nature, xp, .. }`), `gen.pkmn_db()`, `gen.move_db()`
(`get_move(name)`: `Move { move_type, base_power, accuracy, pp, category, .. }`),
`gen.get_fight_category(trainer_name)` (`gym_leader`, `elite_four`, `champion`,
`rival`, `boss`, `team_leader`, `post_game`; `None` for ordinary trainers),
`gen.get_generation()`. Router versions are `"Red"`, `"Blue"`, ... `"White 2"`
plus custom gens (`state::router_versions`); `state::dex_game_for_version`
maps one to its Dex game. Router species names resolve to Dex keys with
`xpr_dex::resolve_species` (for sprites and links to the Pokédex). Router move
names are the router's (`"Double Edge"` in gen 1); look them up in
`gen.move_db()`, not in `xpr-dex`.

## Writing a tab

- A tab lives in its own files under `src/views/<tab>/` behind the entry
  points the shell calls (`ui`, `list_ui`, `detail_ui`, `spotlight_rows`, ...).
  The comparison views reuse the Pokédex's (`stats`, `ranking`,
  `effectiveness`, `context_menu`) and the movepool's (`rows`, `table`,
  `move_row`, `diff_marks`) public pieces.
- Shared files (`lib.rs`, `shell.rs`, `state.rs`, `widgets.rs`, `palette.rs`,
  `images.rs`, `testkit.rs`) are used by every tab. A change there needs every
  tab's tests (`cargo test -p xpr-dex-ui`).
- The tabs were first written in parallel, one agent per feature, under the
  rules below. A few helpers were copied between modules
  (`compare/rank.rs` from `pokedex/ranking.rs`, small painting helpers);
  merge them when you next touch them.
- Per frame you get `cx: &mut DexCx`: `cx.theme`, `cx.registry`, `cx.route`
  (the open route's version / solo species), `cx.state` (shared selection and
  `cx.state.settings`, the persisted `DexSettings`; call `cx.state.touch()` after
  changing settings), `cx.images` (sprites, category icons), `cx.actions`
  (push `DexAction`s for the host: `AddTrainerToRoute`, `OpenUrl`, `Toast`).
- Selection helpers on `DexState`: `select_species`, `compare_with`,
  `triple_compare`, `self_compare`, `exit_compare`, `set_game`, `set_version`,
  `request_damage` (switches to the Damage tab with a request).
- Fonts: `palette::px(theme, 12.0)` / `px_bold` take CSS pixel sizes, so map
  Tailwind directly (`text-[10px]` 10, `text-xs` 12, `text-sm` 14, `text-base` 16,
  `text-lg` 18, `text-xl` 20, `text-2xl` 24). Colours: `palette::GRAY_*` are Solodex's
  navy grays (its `tailwind.config.js` replaces Tailwind's), the others
  Tailwind's; the page background is `GRAY_900` as in Solodex; `palette::type_color`, `stat_color`, `category_color`,
  `game_color`, `trainer_category_color`, `hex("#...")`.
- Widgets: `widgets::type_badge` (click = matchups popover), `type_chip`,
  `section_label`, `small_button(_ex)`, `menu_entry`, `click_popover`,
  `context_menu`, `modal` (router-styled dialog), `game_toggle`,
  `sort_header_cell` + `SortDir`, `search_field`, `placeholder`, `hairline`,
  `paint_glossy`, `spotlight` (search overlay). Images:
  `images::sprite_widget`, `cx.images.sprite(ctx, species, dex, SpriteSize::Small|Full)`,
  `images::category_icon_widget`, `images::paint_fit`. ui-kit:
  `xpr_ui_kit::widgets::{Entry, SearchableDropdown, AmountEntry, checkbox, ...}`.
- Long lists: `egui::ScrollArea::vertical().show_rows(ui, row_h, n, |ui, range| ..)`
  (Solodex's `VirtualList`). Give every ScrollArea / Grid / popup a unique
  `id_salt` / `Id`.
- Don't run `cargo fmt` / `rustfmt`: the repo has no rustfmt config and is
  not rustfmt-formatted (long lines); format by hand in the surrounding style.
- `Stroke::new(1.0_f32, ..)`: write float literals passed to egui generics with
  `_f32` (plain `1.0` is a future-incompat warning).
- **Raw input must respect dialogs** (repo `CLAUDE.md`): prefer real widgets
  (`ui.interact`, `allocate_exact_size(.., Sense::click())`, `Response::clicked()`).
  Any raw read (`ui.input(|i| i.pointer..)`, `key_pressed`, `consume_key`)
  first checks `xpr_ui_kit::modal::pointer_blocked(ui)` (pointer) or
  `behind_modal(ui)` (keys) and stands down when true. Keys also stand down
  while a text field has focus (`ui.ctx().wants_keyboard_input()`).
- Not ported: graphic exports (html-to-image PNG buttons, bulk export), the
  Bulbapedia article popovers (Electron-only; offer an "Open on Bulbapedia"
  link via `DexAction::OpenUrl("https://bulbapedia.bulbagarden.net/wiki/<Name>_(move)")`
  etc. instead), the issue reporter, map links, the Route tab.

## Build, test, look

One tab on its own (quick, and what to use while a tab is broken):

```text
cd rust
cargo check -p xpr-dex-ui --no-default-features --features <tab>
cargo test  -p xpr-dex-ui --no-default-features --features <tab> --test <tab>
cargo run   -p xpr-dex-ui --no-default-features --features <tab> --example dex_png -- \
    --out <scratch dir>/shot.png --tab <tab> [--game G] [--version V] [--species S] \
    [--trainer T] [--click x,y] [--hover x,y] [--key F3] [--type text] [--dump-text]
```

`cargo test -p xpr-dex-ui` runs every tab's tests; the app builds every tab
(xpr-app depends on the default features). Tests go in
`rust/crates/xpr-dex-ui/tests/<tab>.rs` starting with
`#![cfg(feature = "<tab>")]`, driven by `xpr_dex_ui::testkit::DexDriver`
(headless page: `frame`, `click`, `right_click`, `hover`, `key`, `type_text`,
`shows(text)`, `texts`, `take_actions`, `save_png`). Look at your PNGs (the
Read tool shows images) and compare with what Solodex renders; iterate until
the layout is right at 1600x1000 and still usable at 1100x750.
